# LESSONS

1. (8.11.2026) The tasks folder id under /private/tmp/claude-501/<project>/ is not always the session id (after a resume it differs); agent task files are symlinks into the session's transcript, so a session is matched by the link target.
2. (8.11.2026) The Pixel shows three times in `adb devices` (USB, two network addresses); dedupe by ro.serialno.
3. Never load transcripts: an agent's description is in its `.meta.json`.
4. (8.11.2026, v2) Modes per session come from files, no extra hooks: `~/.cache/mantra-bar/<sessionId>.json` (the status line writes model, RC, context %, 5-hour and week %), `<sessionId>.router.json` (router mode gate/auto/off and the pick), `~/.cache/claude-usage.json` (account usage with reset times), the last 300 KB of the transcript (last main-thread model id, `effort`, the `mode` entry = permission mode; "normal" is shown as default), settings.json (default model, remoteControlAtStartup, router plugin), `~/.claude.json` (MCP server names only), the session file's `bridgeSessionId` (RC bridge).
5. Missing, shown as "unknown": fast mode (no file carries it per session; settings only if `fastMode` is set), the session's live model when the transcript tail has none, anything for Claude Code in Termux on the phones (not running now, and no state file is readable over adb without Termux's run-as), mantra-bar on a phone. A router in mode `off` is shown as BYPASSED (Marko, 5.11.2026: Opus on every prompt).
6. The statusline writes `<sessionId>` files only while that session's status line runs (every 60 s); a stale file means a stale value.
7. (8.11.2026, v3) Marko: the title is "Agent Manager (CEO) (Mantra)". The totals tiles are SOLO filter buttons (AX ids solo-done, solo-running, solo-paused, solo-failed, solo-todo, solo-sessions, solo-vm; SHOW ALL = solo-clear): a task status hides every other task and every non-plan panel; SESSIONS shows only the Mac sessions panel; VM only the chromium-vm panel; click again to show all. Test: `--shot out.png --solo running --width 620`.
8. A local `func` inside a SwiftUI body or a ViewBuilder closure breaks the compile ("closure containing a declaration"); use global or static functions. The window's native title drew a second title over the row: keep window.title empty and find the window by identifier.
9. (8.11.2026, v4) Sessions everywhere = the master's ~/.mantra-os/sessions.json (ListAgents: Remote Control and cloud sessions, which only a session can list) merged with what the app probes (Mac sessions by name, chromium-vm tmux claude, Claude Code on phones over adb), deduped by name, each row with its source and "as of". Devices come from `tailscale status --json` (the Mac CLI inside Tailscale.app); online android peers with port 5555 open get an `adb connect`, which is how the Nothing Phone (adb model A142) appears. Not readable: the state of a Remote Control or cloud session other than what the master wrote; Mantra Remote's door (:8841) shows the phone's screen, not its processes, so it is not used.
10. (8.11.2026, v5) RETIRE queues {action:"retire", session, device, kind} for the master and shows progress from ~/.mantra-os/retire/<slug>.json (checking, clean, blocked, retired); the prompt every session gets is retire-prompt.txt (bundled). The app never deletes or archives anything itself.
11. (9.11.2026, v6) "Every session: modes and usage" is now an iTerm-style STATUS BAR pinned to the bottom (always visible, scroll area above it): one line for all sessions (default model, effort, RC at start, router plugin, fast, 5h and week with reset), one line per Mac session (name, model, effort, permission, RC, router and pick, ctx, 5h, week, agents, MCP). Segments are one wrapping Text with thin dividers, so nothing is cut; usage turns amber from 60 % and red from 85 %. The bar is capped at 118 pt and scrolls if there are many sessions.
